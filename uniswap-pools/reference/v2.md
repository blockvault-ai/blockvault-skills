# Uniswap V2 — Classic LP workflow

V2 is the classic full-range AMM. Liquidity is spread over the whole price curve `[0, ∞)` — no NFT, no range choice, no out-of-range risk. Capital-inefficient but zero range risk.

## Contents
- Open a position
- Increase / decrease
- Exit

## Open a position workflow

Before starting the make sure the checklist is complete

Checklist:
  [] The user has BOTH sides of the pair in their wallet.
  [] The user has enough native gas to pay for the LP transaction.

### 1. Fund both sides

Both tokens must be in the wallet before minting. If one is missing, fund it with `blockswap` (see the `blockswap` skill). Confirm native gas is present.

### 2. Open the position (default: one call)

Use `POST /lp/prepare` — it checks approvals AND builds the create transaction in a single call. No separate `check_approval` is needed:

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V2","poolReferenceIdentifier":"<PAIR_ADDRESS>","token0Address":"<A>","token1Address":"<B>","independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"simulateTransaction":true}'
```

`prepare` returns a combined `transactions[]` envelope (approvals first, then the create).

### 2b. Manual fallback (check_approval + create_classic)

Only if `prepare` is unavailable. Approve BOTH tokens of the pair (with amounts):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/check_approval" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","protocol":"V2","chainId":<CHAIN_ID>,"lpTokens":[{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"}],"action":"CREATE"}'
```

Then `create_classic` with `poolParameters` (no `tickBounds`, no `nftTokenId`). `dependentToken` is optional — omit it and the API computes the optimal amount from current pool reserves (it does NOT swap; the wallet must still hold both tokens):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/create_classic" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","poolParameters":{"token0Address":"<A>","token1Address":"<B>","chainId":<CHAIN_ID>},"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"includeApprovalSimulation":true,"simulateTransaction":true}'
```

**Dependent amount (critical):** `dependentToken` is optional. When omitted, the API computes the other side's amount from current pool reserves — it does NOT auto-swap. The wallet must hold both tokens; if one is missing, fund it with `blockswap` first.

### 4. Verify simulation

`prepare` simulates the create transaction on-chain (`eth_call`) and returns the result under `simulation`:

- `simulation.success == false` → do NOT sign; report `simulation.error` and stop.
- `simulation` missing or `success == true` → the transaction would succeed; sign + notify.
- `transactions[]` empty → no calldata to sign; report and stop (do NOT sign an empty envelope).

The upstream `simulateTransaction` flag only adds a best-effort `gasFee` estimate — it does NOT reliably detect reverts. Trust the `simulation` field from `prepare` instead.

## Increase / decrease

Ask the user which side they want to increase/decrease (token0 or token1).

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/increase" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V2","token0Address":"<A>","token1Address":"<B>","independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"simulateTransaction":true}'
```

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/decrease" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V2","token0Address":"<A>","token1Address":"<B>","liquidityPercentageToDecrease":<PERCENT>,"withdrawAsWeth":false,"simulateTransaction":true}'
```

## Exit
Ask the user if they want to exit fully (100%) or partially (1-99%). Then:

1. `GET /lp/positions/<ADDRESS>` → find the V2 position (no `token_id`).
2. `check_approval` `action:"DECREASE"` with `lpTokens` = the **LP token** (the pair address) — V2 burns your LP token, so it needs allowance:
```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/check_approval" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","protocol":"V2","chainId":<CHAIN_ID>,"lpTokens":[{"tokenAddress":"<PAIR_ADDRESS>","amount":"1"}],"action":"DECREASE"}'
```
3. `decrease` `simulateTransaction:true`, `liquidityPercentageToDecrease:100` → check simulation → sign.

V2 has no separate `claim_fees` — fees are collected automatically on `decrease`.
