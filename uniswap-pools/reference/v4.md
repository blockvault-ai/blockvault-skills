# Uniswap V4 — Concentrated LP with hooks

V4 is concentrated liquidity + hooks. Same as V3 (you pick a price range via `tickBounds`, position = ERC-721 NFT), but pools support hook contracts (dynamic fees, custom curves). Pool id = `(token0, token1, fee, tickSpacing, hooks)`.

## Contents
- Open a position
- Increase / decrease
- Claim fees
- Exit

## Open a position workflow

Before starting the make sure the checklist is complete

Checklist:
  [] The user has BOTH sides of the pair in their wallet.
  [] The user has enough native gas to pay for the LP transaction.

### 1. Fund both sides

Both tokens must be in the wallet before minting. If one is missing, fund it with `blockswap`. Confirm native gas is present.

### 2. Open the position (default: one call)

Use `POST /lp/prepare` — it checks approvals AND builds the create transaction in a single call. No separate `check_approval` is needed:

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V4","poolReferenceIdentifier":"<POOL_ID>","token0Address":"<A>","token1Address":"<B>","fee":<FEE>,"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"simulateTransaction":true}'
```

`prepare` returns a combined `transactions[]` envelope (approvals first, then the create).

#### Range control 
Ask the user for their price range. The user decides the range in terms they understand;

  - `rangePct` — `±X%` around the current price.
  - `priceBounds` — absolute prices `{ minPrice, maxPrice }` (token1 per token0).

```bash
## rangePct 
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V4","poolReferenceIdentifier":"<POOL_ID>","token0Address":"<A>","token1Address":"<B>","fee":<FEE>,"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"rangePct":<PCT>,"simulateTransaction":true}'
## priceBounds
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V4","poolReferenceIdentifier":"<POOL_ID>","token0Address":"<A>","token1Address":"<B>","fee":<FEE>,"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"priceBounds":{"minPrice":<MIN>,"maxPrice":<MAX>},"simulateTransaction":true}'
```

### 2b. Manual fallback (check_approval + create)

Only if `prepare` is unavailable. Approve BOTH tokens of the pair (with amounts):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/check_approval" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","protocol":"V4","chainId":<CHAIN_ID>,"lpTokens":[{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"}],"action":"CREATE"}'
```

Then `create` with `existingPool` + `tickBounds` (same shape as V3; `poolReference` is the V4 pool id). `dependentToken` is optional — omit it and the API computes the other side's amount from current pool state (it does NOT swap; the wallet must still hold both tokens):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/create" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V4","independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"existingPool":{"token0Address":"<A>","token1Address":"<B>","poolReference":"<POOL_ID>"},"tickBounds":{"tickLower":<T>,"tickUpper":<T>},"urgency":"NORMAL","simulateTransaction":true}'
```

**Token order (critical):** pass `token0Address`/`token1Address` exactly as returned — never swap or reorder them.

**Amount (critical):** `independentToken.amount` is in **decimal units, never wei**. For "X USD", use the stablecoin side with `amount: "X"`.

**Dependent amount (critical):** `dependentToken` is optional. When omitted, the API computes the other side's amount from current pool state — it does NOT auto-swap. The wallet must hold both tokens; if one is missing, fund it with `blockswap` first.

**Tick bounds (critical):** `tickBounds` = `{ tickLower, tickUpper }` — integers, multiples of `tickSpacing`, straddling `currentTick`. **`priceBounds` is BROKEN upstream** (returns a `tickPrice` validation error) — never send it to `create` directly. The `prepare` endpoint accepts `priceBounds`/`rangePct` and converts them to `tickBounds` server-side. In the manual fallback, take `tickBounds` from `/pools/recommend` (field `tickBounds`).

### 4. Verify simulation

`prepare` simulates the create transaction on-chain (`eth_call`) and returns the result under `simulation`:

- `simulation.success == false` → do NOT sign; report `simulation.error` and stop.
- `simulation` missing or `success == true` → the transaction would succeed; sign + notify.
- `transactions[]` empty → no calldata to sign; report and stop (do NOT sign an empty envelope).

The upstream `simulateTransaction` flag only adds a best-effort `gasFee` estimate — it does NOT reliably detect reverts. Trust the `simulation` field from `prepare` instead.

## Increase / decrease

Ask the user which side they want to increase/decrease (token0 or token1).

V4 positions are NFTs — `increase`/`decrease` require `nftTokenId` (resolve it from `GET /lp/positions/<ADDRESS>`):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/increase" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V4","token0Address":"<A>","token1Address":"<B>","nftTokenId":"<TOKEN_ID>","independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"simulateTransaction":true}'
```

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/decrease" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V4","token0Address":"<A>","token1Address":"<B>","nftTokenId":"<TOKEN_ID>","liquidityPercentageToDecrease":<PERCENT>,"withdrawAsWeth":false,"simulateTransaction":true}'
```

## Claim fees

`claim_fees` + `tokenId` (only to claim while keeping the position):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/claim_fees" \
  -H "Content-Type: application/json" \
  -d '{"protocol":"V4","walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"tokenId":"<TOKEN_ID>","collectAsWeth":false,"simulateTransaction":true}'
```

## Exit
Ask the user if they want to exit fully (100%) or partially (1-99%). Then:

1. `GET /lp/positions/<ADDRESS>` → resolve `token_id`.
2. `decrease` `simulateTransaction:true`, `liquidityPercentageToDecrease:100` → check simulation → sign.

No approval is needed to decrease/exit — the position NFT is already owned by the wallet. V4 fees are auto-included on full exit; no separate `claim_fees` needed.
