# Uniswap V3 — Concentrated LP workflow

V3 is concentrated liquidity. You pick a price range (`tickBounds`); fees only accrue while the price stays in it. Higher capital efficiency, "out-of-range" risk. Position = ERC-721 NFT (`nftTokenId`).

## Contents
- Open a position
- Increase / decrease
- Claim fees
- Exit

## Open a position workflow

Before starting the make sure the checklist is complete

Checklist:
  [] The user has BOTH sides of the pair in their wallet.
  [] The user has enough native gas to pay for the LP transaction.

### 1. Fund both sides

Both tokens must be in the wallet before minting. If one is missing, fund it with `blockswap`. Confirm native gas is present.

### 2. Open the position

Checks approvals AND builds the create transaction in a single call.

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V3","poolReferenceIdentifier":"<POOL_ADDRESS>","token0Address":"<A>","token1Address":"<B>","fee":<FEE>,"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"simulateTransaction":true}'
```

`prepare` returns a combined `transactions[]` envelope (approvals first, then the create).

#### Range control 
Ask the user for their price range. The user decides the range in terms they understand;

  - `rangePct` — `±X%` around the current price.
  - `priceBounds` — absolute prices `{ minPrice, maxPrice }` (token1 per token0).

```bash
## rangePct 
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V3","poolReferenceIdentifier":"<POOL_ADDRESS>","token0Address":"<A>","token1Address":"<B>","fee":<FEE>,"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"rangePct":<PCT>,"simulateTransaction":true}'
## priceBounds
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/prepare" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V3","poolReferenceIdentifier":"<POOL_ADDRESS>","token0Address":"<A>","token1Address":"<B>","fee":<FEE>,"independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"priceBounds":{"minPrice":<MIN>,"maxPrice":<MAX>},"simulateTransaction":true}'
```

### 4. Verify simulation

`prepare` simulates the create transaction on-chain (`eth_call`) and returns the result under `simulation`:

- `simulation.success == false` → do NOT sign; report `simulation.error` and stop.
- `simulation` missing or `success == true` → the transaction would succeed; sign + notify.
- `transactions[]` empty → no calldata to sign; report and stop (do NOT sign an empty envelope).

The upstream `simulateTransaction` flag only adds a best-effort `gasFee` estimate — it does NOT reliably detect reverts. Trust the `simulation` field from `prepare` instead.

## Increase / decrease

Ask the user which side they want to increase/decrease (token0 or token1).

V3 positions are NFTs`increase`/`decrease` require `nftTokenId` (resolve it from `GET /lp/positions/<ADDRESS>`):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/increase" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V3","token0Address":"<A>","token1Address":"<B>","nftTokenId":"<TOKEN_ID>","independentToken":{"tokenAddress":"<TOKEN_ADDRESS>","amount":"<DECIMAL>"},"simulateTransaction":true}'
```

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/decrease" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"protocol":"V3","token0Address":"<A>","token1Address":"<B>","nftTokenId":"<TOKEN_ID>","liquidityPercentageToDecrease":<PERCENT>,"withdrawAsWeth":false,"simulateTransaction":true}'
```

## Claim fees

`claim_fees` + `tokenId` (only to claim while keeping the position):

```bash
curl -sS -X POST "https://402.blockvault.ai/api/v1/uniswap/lp/claim_fees" \
  -H "Content-Type: application/json" \
  -d '{"protocol":"V3","walletAddress":"<ADDRESS>","chainId":<CHAIN_ID>,"tokenId":"<TOKEN_ID>","collectAsWeth":false,"simulateTransaction":true}'
```

## Exit

Ask the user if they want to exit fully (100%) or partially (1-99%). Then:

1. `GET /lp/positions/<ADDRESS>` → resolve `token_id`.
2. `decrease` `simulateTransaction:true`, `liquidityPercentageToDecrease:100` → check simulation → sign.

No approval is needed to decrease/exit — the position NFT is already owned by the wallet. V3 fees are auto-included on full exit; no separate `claim_fees` needed.
